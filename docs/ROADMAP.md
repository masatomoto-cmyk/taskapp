# 学習ロードマップ（転職・案件獲得を見すえて）

2026-10-31 作成。もとにしたのは NotebookLM「単価アップ（yuki_engineer）」の動画 29 本で、「転職・案件獲得で求められる技術」を聞いた結果。

## 動画で「現場が見ている」と言われていた技術

| 技術 | なぜ必要か（動画の主張） |
|---|---|
| 言語・フレームワーク | 文法や経験年数ではなく、現場の課題を解く「道具」として使えるか |
| DB（スキーマ設計・データの流れ） | DB から画面までの流れがわかると、全行読まずに構造やエラー原因をつかめる |
| テスト | 手動確認から抜け出し、機能追加やリプレイス時のデグレ（前は動いていたものが壊れること）を防ぐ |
| Git・プルリク | チームでコードを共有し、レビューを受ける前提になる |
| コードレビュー | AI や他人が書いたコードの誤り・保守しにくさ・障害の危険を、人の目で見極める |
| コードリーディング | 上から1行ずつ読まずに構造をつかみ、ログからエラーの場所を逆にたどる |
| 設計 | データが増えても、機能を足しても壊れにくい構造にする。「なぜこの構成にしたか」を説明できる |
| インフラ・クラウド | アプリの知識と合わせて全体の構成がわかると、障害対応や改善提案ができる |
| AI ツールの活用 | 調べもの・実装・エラー調査を速くし、人は設計や課題解決に集中する |
| 個人開発の本番運用 | 作って終わりにせず公開し、エラーログ対応や遅さの改善を経験する |

キャリアの順番は「**アプリ側（フロント・バックエンド）から入り、インフラは後から少しわかる**」状態が需要が高い、とも語られていた。
また、面接では技術の羅列より「**なぜその設計にしたか**」「**どんな課題をどう解決したか**」を話せるかが見られる。

## ロードマップ

○ = その段階で身につける技術。taskapp を育てながら、全部をポートフォリオに残す。

| 段階 | やること | 身につく技術 |
|---|---|---|
| **1. 土台**（今ここ） | テーブル設計、DB 接続（課題B・C） | DB 設計、データの流れ |
| **2. CRUD** | タスクの作成・一覧・更新・削除 | 言語の基礎、DB、**Git・プルリク**（ここから毎回） |
| **3. 認証** | 登録・ログイン・自分のタスクだけ操作 | セキュリティ、認可、設計 |
| **4. テスト** | PHPUnit で ②③ のテスト | テスト設計、デグレ防止 |
| **5. バッチ** | 期限切れタスクの一括処理 | 冪等性、ログの残し方 |
| **6. 公開（最低限）** | Docker 化 → クラウドに公開。まずは動けばよい | インフラの入口 |
| **7. フロント** | HTML・CSS を固める → TypeScript → React で画面を作り直す。PHP は JSON を返す API にする | 求人の多いフロント技術、画面と API の分け方 |
| **8. フレームワーク** | API 側を Laravel で作り直し、素の PHP 版と比べる | フレームワーク、設計の比較 |
| **9. 運用を深める** | エラーログを見る、遅いところを直す、テストとデプロイの自動化（CI） | 本番運用、DevOps・クラウド |

**2026-11-03 の見直し**：フロント（React）を「選択」から必須にして、Laravel より前に移した。サーバー側（DB・認証・テスト）がわかるうえで画面も作れる人は少なく、強みになると考えたため。インフラは公開に必要な最低限だけ先にやり、運用の深い部分は最後に回した。

### どの段階でも続けること

| 習慣 | 具体的にやること | 鍛えられる技術 |
|---|---|---|
| **設計メモ** | 決めたこと・理由・他の案を README の「設計で考えたこと」に1行ずつ足す | 設計、面接で語る力 |
| **レビューを受ける・する** | 自分のプルリクを Claude（先輩役）がレビュー。ときどき「AI が書いたバグ入りコード」を渡すので、本人がレビューする | コードレビュー |
| **コードを読む練習** | 新しい機能を書く前に、既存のコードで「画面 → PHP → DB」の流れを指でたどる。エラーはログから原因の行をたどる | コードリーディング |
| **困ったことの記録** | 詰まったこと・原因・解決を作業記録に残す | 面接で話す「課題解決エピソード」 |

### AI ツールとの付き合い方
- **段階1〜5**：VS Code の先回り入力は止めたまま。自分で書く力を先につける。Claude は先生・レビュー役
- **段階6以降**：Claude Code などを「助手」として使い始める。ただし、AI が出したコードは**自分で説明できるまで採用しない**（レビューの練習を兼ねる）

## ポートフォリオに残すもの
- GitHub：Issue → プルリク → レビュー → 修正の履歴
- README：何ができるか、使った技術、設計で考えたこと、困ったことと解決
- 公開 URL（段階6以降）
