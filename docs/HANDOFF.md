## 作るアプリと進め方
タスク管理アプリ「taskapp」を、まず次の4段階で育てる（ロードマップの段階2〜5）。

| 段階 | 作るもの |
|---|---|
| ① CRUD | タスクの作成・一覧・更新・削除 |
| ② 認証 | ユーザー登録・ログイン・ログアウト。自分のタスクだけ操作できる |
| ③ テスト | PHPUnit で ①② のテスト |
| ④ バッチ | 期限切れタスクを一括で expired にする CLI スクリプト（`bin/`） |

- 画面（`public/`）と処理（`src/`、namespace `App\`）を分ける
- Composer のオートロード設定済み（`composer.json`、`vendor/` は Git に入れない）
- **レッスン1が終わったら**：GitHub にリポジトリを作る（公開か非公開かは本人に確認）。レッスン2からは「Issue → ブランチ → プルリク → Claude が先輩役でレビュー → 修正 → マージ」で進める

### 説明済みのこと（もう一度説明しなくてよい）
- テーブル設計の考え方、型の選び方、NULL と DEFAULT
- フォーリンキー（外部キー）が必要な理由
- MySQL のエラーメッセージの読み方（番号＝種類、「付近」の直前に原因、phpMyAdmin は最初のエラーで止まる）
- `require` と `require_once` の違い、オートロードがあると入口で1回 autoload.php を読むだけでよいこと
- `final class`（継承禁止の印。JS の const とは別物）、`namespace`（クラスの住所）、`declare(strict_types=1)`（型を厳しくチェック）、`public static function connect(): PDO`（各単語の意味）、`private static ?PDO $pdo = null`（接続を入れる空の箱、使い回しのため）
- 以前のコードの直したい点（if の外に処理がはみ出す、`$e->getMessage()` を画面に出す、クラスの中で `exit()`）
